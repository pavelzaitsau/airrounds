# T10 acceptance

T10 closed on November 21, 2026. The Mac verified every PCAP that the final
build saved on the bench.

T10 added the **Capture mode** choice with Beacon and two placeholders, and
moved Beacon behind a capture-mode contract in the ESP32 firmware and the
Flipper app. The [requirement](ui-ux/capture-modes.md) defines the screens,
and the [design](capture-modes-design.md) defines the contract, the
admission checklist, and the reserved protocol. Beacon behaves as in T9.

## Software evidence

The closure tree passed `make check`, `make asan`, `make tsan`, and
`make embedded`. The final ESP32-S2 source build ID is `3530d0bd020cd7ec`.

| Check | Evidence |
| --- | --- |
| Beacon unchanged | `tests/storage/capture_mode_test.cpp`: `BeaconMode` and `PassiveSession` accept the same frames and close the window at the same time. The file matches the T9 header and frame bytes. The T8 and T9 host tests pass unchanged. |
| Frame types and chains | The same test: the shared writer refuses an undeclared frame type, an oversize frame, and an empty set before it creates the file, and saves a chain in order. |
| Mode table, labels, and locks | `tests/uart/capture_mode_labels_test.cpp` covers the label slots, the list row text, and every row of the lock table for frame-found, absence, and unknown modes. The confirmed-absence result has no outcome value until step R5, so no test covers it yet. |
| Screens | The UI emulator checks the five-item menu, the scroll marks, the **Capture mode** screen, and its locks. |
| Mockup | `docs/ui-ux/scan-prototype.test.cjs`: 26 tests. |
| Review | Independent review rounds ran on the change and then on the squashed commit. Every finding was fixed, and the rounds ended with one that found nothing. |
| Memory | 52,160 of 65,536 bytes of ESP32 global RAM; 1,448 of 2,048 bytes on the Flipper app path. |

## Next steps

Protocol step R5 and contract step R6 come with the first real mode. They
need answers to the open questions in the design: what Todo A and Todo B
do, which frame types they need, and what the Mac checks for a confirmed
absence. The `round_status_mode` reply has no spare byte: before R5 adds
the `mode` field, the board must leave the round fields off a rejected
reply.
