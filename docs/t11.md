# T11 EAPOL capture

T11 adds an EAPOL capture mode to the T10 capture-mode contract. It replaces
the Flipper placeholder Todo A with a real mode that records the EAPOL-Key
frames of the WPA 4-way handshake for the round's target access point. The
mode saves the frames: `found` plus a record list maps to `saved` on the
existing contract.

T11 is receive-only. It adds no transmission, no deauthentication, and no
decryption. Two independent gates keep every non-EAPOL data frame out of the
capture: the mode's `onFrame` filter, and an ethertype check in the shared
writer.

The design and the reserved protocol are in the
[capture modes design][design]. The screens and the label rules are in
[Capture modes on Flipper][ui]. The wire format of the reserved commands is in
the [UART protocol][uart].

## Scope and policy

[Acceptable use][aup-modes] owns the rules for every capture mode. It already
permits handshake capture under four limits: own or permitted networks,
research use, receive-only, and no decryption. T11 builds the first mode under
those limits and does not restate them. The
[admission entry](#eapol-mode-admission-entry) shows how the EAPOL mode meets
each limit.

The receive-only invariant is the one the [T9 security assurance gap][t9-gap]
relies on. T11 keeps it, and T11 builds the source check that
[acceptable use][aup-safeguards] lists as planned: a host test fails
`make check` when `firmware/esp32/**` holds a transmit call. See
[Tests](#tests).

The round's target profile is a scope aid, not a legal boundary.
`EapolMode::onFrame` accepts a frame only when its BSSID, taken by the DS bits,
equals the BSSID of the access point the visit targets. The operator chooses
that access point, and the operator owns the decision that it is in scope.

### Clean-room parser

Write the EAPOL parser from IEEE 802.11-2020, clause 9 for the MAC header and
clause 12.7 for the EAPOL-Key frame and the 4-way handshake. Copy no code from
another project. A feasibility assessment of an existing firmware found three
parse defects and three classifier gaps. T11 does not reuse that firmware. It
turns each defect into a test case in [Tests](#tests):

| Defect class | The rule that prevents it | Test |
| --- | --- | --- |
| A read past the end of a short frame | Every `size` check precedes the read it guards | A truncated frame at each parse step |
| A wrong BSSID for a client-to-AP frame | The DS-bit BSSID map | One frame per DS form |
| A wrong header length for a QoS or HT data frame | The header-length rule | A QoS frame, and a QoS frame with HT Control |
| A group rekey counted as a handshake message | The Key Type bit check | A group message 1 and 2 |
| A WPA1 message 3 counted as message 3 | The Secure bit in the classifier | A WPA1 message 3 |
| A non-Key EAPOL packet counted as a message | The packet type check | An EAP packet and an EAPOL-Start |

## EAPOL mode admission entry

[Admission checklist][design-admission], in the order the checklist defines. A
mode without an entry stays unavailable. The entry uses inline links that
resolve from both `docs/t11.md` and `docs/capture-modes-design.md`, so it
pastes without broken links.

### EAPOL mode

The mode records the EAPOL-Key frames of the WPA 4-way handshake for the
round's target access point.

- **Receive only.** The mode needs no transmission. The contract has no
  transmit call, and the mode adds none. It waits for a client to join on its
  own and records the handshake the join produces. It never forces a
  reconnect.
- **Frame types.** The mode declares `dataFrames` only. An EAPOL frame is a
  data frame that carries the IEEE 802.1X ethertype `0x88 0x8e` after its
  LLC/SNAP header. The receive filter passes `WIFI_PROMIS_FILTER_MASK_DATA`.
  The mode needs no management or control frames.
- **Records.** The mode saves a chain of one to four frames, one per handshake
  message held. Each frame buffer is 512 bytes, and the mode keeps four of
  them, so the chain costs 2,048 bytes of static RAM plus the per-message size
  and timestamp. The mode drops a frame larger than 512 bytes and never
  truncates it, so the PCAP never holds a partial record. `make embedded` is
  the memory gate; see [RAM budget](t11.md#ram-budget).
- **Identifiers.** The PCAP holds the whole EAPOL frames, so the target BSSID,
  the client MAC address, and the EAPOL-Key fields reach the card. The journal
  records the target BSSID and the channel, as for Beacon. The Flipper screen
  shows the per-point result label only. No client MAC address reaches the
  screen.
- **Target.** The mode drops every frame whose BSSID, taken by the DS bits, is
  not the access point the visit targets. It drops a 4-address WDS frame,
  which has no single BSSID.
- **Payload.** The mode decrypts nothing and derives no key, PMK, PTK, PMKID,
  or passphrase. It saves only the raw frame bytes. Those bytes carry
  key-derived values: message 1 can carry the PMKID, and messages 2 to 4 carry
  the MIC. Either value allows an offline guess of the passphrase, so
  [acceptable use](acceptable-use.md#capture-modes-in-scope) treats the
  capture as being as sensitive as the passphrase, and
  [data handling](acceptable-use.md#data-handling) governs it.
- **Evidence.** A point succeeds when the mode saves at least one EAPOL-Key
  frame for the target; the point result `saved` reports that saved frame,
  not a completed join. The Mac check `tools/mac/check_pcap.py --eapol`
  confirms that every saved frame is an EAPOL-Key frame for the target BSSID.
  It reports which handshake messages the file holds per client, and whether
  one client completed a join. See
  [Success semantics](t11.md#success-semantics) and
  [Mac check](t11.md#mac-check).
- **Legal basis.** An own network, or a network whose owner permits the test
  in writing, under the scope and limits in
  [acceptable use](acceptable-use.md).

## Success semantics

The success judgement splits in two. The firmware and the Flipper label report
a saved frame. The Mac check reports a completed join.

| Judgement | Rule | Reported by |
| --- | --- | --- |
| Point success | At least one EAPOL-Key frame saved for the target | `EapolMode::finish` returns `found`, the point result is `saved` (digit 2), the Flipper shows "Captured" |
| Completed join | Messages 3 and 4 from one client | `tools/mac/check_pcap.py --eapol` only |

`EapolMode::finish` returns `found` when `held_ != 0`, so a lone message 1 for
the target still saves a PCAP and reports "Captured". The firmware never gates
`found` on messages 3 and 4. The Mac check groups frames by client and judges
the join.

`EapolMode::done` returns early once messages 3 and 4 from one client are both
held, because a complete handshake needs no more time. That early stop is a
timing optimisation, not the success rule. A point that stops early and a point that
fills its budget both report `saved` when any message is held.

## Firmware: the EAPOL mode

### Mode identifier

```cpp

```

The wire ID `01` matches the Flipper descriptor and the Todo A slot that T10
reserved.

### Shared EAPOL parser

Add `firmware/esp32/session/eapol.h` with the pure parse functions the mode
calls. The functions read a frame without the FCS, the form `onFrame`
receives. They allocate nothing and have no side effect.

| Function | Returns |
| --- | --- |
| `const uint8_t* eapolBssid(const uint8_t* frame, size_t size)` | The BSSID for the frame by its DS bits, or `nullptr` for a 4-address WDS frame or a frame shorter than a 24-byte header. |
| `size_t eapolHeaderLen(const uint8_t* frame)` | The 802.11 MAC header length: 24, plus 2 for a QoS data subtype, plus 4 for HT Control. |
| `bool isEapolKeyFrame(const uint8_t* frame, size_t size)` | True when the frame carries an LLC/SNAP header, the ethertype `0x88 0x8e`, and EAPOL packet type 3 (Key). It reads no further. |
| `uint8_t classifyKeyInfo(uint16_t keyInfo)` | The handshake message 1 to 4, or 0 for no match. It returns 0 when the Key Type bit is clear, which covers a group rekey, and 0 for a WPA1 message 3. |

The DS-bit BSSID map keeps messages 2 and 4, which a client sends to the access
point.

| ToDS | FromDS | `frame[1] & 0x03` | BSSID address | Offset | Frames kept |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | `0x00` | Addr3 | `frame + 16` | Same-BSS data |
| 1 | 0 | `0x01` | Addr1 | `frame + 4` | Messages 2 and 4, client to AP |
| 0 | 1 | `0x02` | Addr2 | `frame + 10` | Messages 1 and 3, AP to client |
| 1 | 1 | `0x03` | none | dropped | WDS has no single BSSID |

The header length sums the present fields. The 4-address case never reaches
`eapolHeaderLen`, because `eapolBssid` drops a WDS frame first.

| Component | Size | Condition |
| --- | --- | --- |
| Base MAC header | 24 | Always, the three-address form |
| QoS Control | +2 | A QoS data subtype: `frame[0] & 0x80` |
| HT Control | +4 | QoS present and the Order bit `frame[1] & 0x80` |

The HT Control test gates on QoS as well as the Order bit. On a non-QoS data
frame the Order bit is the legacy strictly-ordered flag, not an HTC marker, so
it adds no field.

The key-info classify reads the field big-endian,
`frame[off + 5] << 8 | frame[off + 6]`, where `off` is the EAPOL header start.

| Bit | Mask | Meaning |
| --- | --- | --- |
| 3 | `0x0008` | Key Type: 1 is pairwise, 0 is group |
| 7 | `0x0080` | Key ACK |
| 8 | `0x0100` | Key MIC |
| 9 | `0x0200` | Secure |

| ACK | MIC | Secure | Message |
| --- | --- | --- | --- |
| 1 | 0 | 0 | 1 |
| 0 | 1 | 0 | 2 |
| 1 | 1 | 1 | 3 |
| 0 | 1 | 1 | 4 |

The table applies only when the Key Type bit is set; a clear Key Type bit
returns 0 first. Any other combination returns 0. A WPA1 message 3 has
`secure = 0` and returns 0, so the mode records no message for it.

### The mode class

Add `firmware/esp32/session/eapol_mode.h` with
`session::EapolMode : public CaptureMode`, wire ID `0x01`. It mirrors the shape
of `BeaconMode`.

```cpp
static constexpr size_t maxEapolFrameSize = 512; // One EAPOL-Key frame with encrypted key data.
static constexpr size_t messageCount = 4;        // Messages 1 to 4.
```

The per-frame buffer is 512 bytes. An EAPOL-Key message 3 carries encrypted key
data: the GTK KDE, the RSN and RSNXE elements, and, with 802.11w, the IGTK and
BIGTK KDEs. The 802.11 header (up to 30 bytes), the LLC/SNAP header (8 bytes),
the EAPOL header (4 bytes), and the fixed EAPOL-Key fields (95 bytes) take 137
bytes, so 512 leaves 375 bytes for key data. A 384-byte buffer leaves only 247
and can drop a large message 3, which breaks the join check. 512 is below the
2,304-byte snap length (`pcap_record.h:35`), so the writer never truncates a
buffered frame.

The mode holds one buffer per message, the target, the budget, and the start
time.

| Member | Type | Role |
| --- | --- | --- |
| `frames_` | `uint8_t[messageCount][maxEapolFrameSize]` | The frame per held message. |
| `sizes_` | `uint16_t[messageCount]` | The frame size per held message. |
| `timestamps_` | `uint32_t[messageCount]` | The elapsed time per held message. |
| `held_` | `uint8_t` | A bitmask of the messages held, bit 0 for message 1. |
| `target_` | `Target` | The round's BSSID and channel. |
| `budgetUs_` | `uint64_t` | The point's share of the round. |

The contract calls behave as follows.

| Call | Behaviour |
| --- | --- |
| `id()` | Returns `CaptureModeId::eapol`. |
| `needs()` | Returns `{storage::dataFrames}`. |
| `reset()` | Clears `held_`, the sizes, and the timestamps. |
| `begin(target, budgetUs)` | Stores `target_` and `budgetUs_`, clears state, returns true. |
| `onFrame(...)` | Filters and buffers an EAPOL-Key frame. See the pseudocode below. |
| `done(elapsedUs)` | Returns true when `elapsedUs + saveReserveUs >= budgetUs_`, with the 3-second reserve of [Timing](#timing), or when messages 3 and 4 are both held and come from one client. |
| `finish()` | Returns `found` when `held_ != 0`, else `not_observed`. |
| `recordCount()` | The number of set bits in `held_`. |
| `record(index)` | The `index`-th held frame in capture order, sorted by `timestamps_`. |

`record` keeps the capture order that the contract
(`capture_mode.h`, `pcap_record.h`) requires. The mode keeps the latest frame
per message, so message order and capture order can differ: a repeated
message 1 can arrive after message 2. Sorting by timestamp keeps the PCAP
timestamps monotonic. Four records need no more than a fixed four-element
index sort; it allocates nothing.

The early stop in `done` compares the client of message 3 with the client of
message 4. Message 3 goes from the access point to the client, so its client is
Addr1 (`frames_[2] + 4`). Message 4 goes from the client to the access point,
so its client is Addr2 (`frames_[3] + 10`). When the two differ, the visit
keeps listening until its budget ends, because a mixed pair is no completed
join. The comparison is one `memcmp` of 6 bytes and needs no extra RAM. The
board still reports no join; the Mac check owns that judgement.

`finish` returns `found` for any held message, not only a complete handshake;
the [success split](#success-semantics) governs this. The mode never returns
`error`; a radio or storage failure comes from `PassiveVisit`, not the mode.

### onFrame

The function carries the per-frame half of the EAPOL-only guarantee. It rejects
before it parses, because the data filter delivers every data frame on the
channel under the receive lock.

```text
onFrame(frame, size, channel, elapsedUs):
  if channel != target_.channel: return false          # honour the tuned channel
  if size < 24: return false                            # need a full MAC header
  if (frame[0] & 0x0c) != 0x08: return false            # data frames only
  if (frame[1] & 0x40) != 0: return false               # Protected: the body is encrypted
  bssid = eapolBssid(frame, size)                       # DS-bit address, null for WDS
  if bssid == null: return false
  if memcmp(bssid, target_.bssid, 6) != 0: return false # reject other BSSIDs first
  if not isEapolKeyFrame(frame, size): return false     # LLC/SNAP, 0x888e, type 3, size checked
  off = eapolHeaderLen(frame) + 8                        # EAPOL header start
  if size < off + 7: return false                       # version, type, length, key_info
  key_info = frame[off + 5] << 8 | frame[off + 6]
  msg = classifyKeyInfo(key_info)                       # 1..4; 0 for group, WPA1 3, or no match
  if msg == 0: return false
  if size > maxEapolFrameSize: return false             # never truncate a record
  memcpy(frames_[msg - 1], frame, size)                 # keep the latest frame per message
  sizes_[msg - 1] = size
  timestamps_[msg - 1] = elapsedUs
  held_ |= 1 << (msg - 1)
  return true
```

The order matters. The type check comes first, because the QoS rule in
`eapolHeaderLen` reads the subtype bits as a data subtype; the receive filter
already passes data frames only, and the check keeps the parser correct when a
test calls it directly. A frame with the Protected bit set carries an encrypted
body, so its LLC/SNAP bytes are ciphertext and must not be parsed. The BSSID
reject comes before `isEapolKeyFrame`, so a frame from another network costs
one 6-byte compare. `isEapolKeyFrame` checks the size before each read it
makes: the header length plus 8 bytes for LLC/SNAP and the ethertype, then 2
more for the EAPOL version and packet type. The `size` checks precede every read, so a short frame never reads out of
bounds. The mode drops a frame over the buffer instead of truncating it, so the
saved record length always matches the original length.

### Journal counter fix

The journal underflows for a data mode. `onPacket` increments
`point.managementFrames` only for a management frame (line 218), and
`point.acceptedBeacons` for any accepted frame (line 223). The journal emits
`point.managementFrames - point.acceptedBeacons` as `filtered_frames`, an
unsigned `uint32_t`. For an EAPOL round `managementFrames` stays 0 while
`acceptedBeacons` rises, so the subtraction underflows to about 4.29e9.

Fix the counters to count the mode's declared frame type, and rename them so
the journal does not label a data count as management.

1. In `firmware/esp32/uart/session_journal.h`, rename the `VisitStatistics`
   fields `managementFrames` to `observedFrames` and `acceptedBeacons` to
   `acceptedFrames`.
1. In `passive_visit.h`, replace the management-only predicate at line 217
   with the mode's declared type: increment `observedFrames` when
   `(frameType & mode_->needs().frameTypes) != 0`. Increment `acceptedFrames`
   when `onFrame` accepts, as before. The receive filter passes only declared
   types and the mode accepts only declared types, so
   `acceptedFrames <= observedFrames` always, and the subtraction cannot
   underflow.
1. In `session_journal.h`, rename the journal labels `management_frames=` to
   `observed_frames=` and `accepted_beacons=` to `accepted_frames=`, and keep
   `filtered_frames=` as `observedFrames - acceptedFrames`.
1. Add `mode=<name>` to the second header line, after `radio=passive`. The
   journal reads the wire ID from `report.status` (the `RoundStatus` field of
   [PassiveVisit wiring](#passivevisit-wiring)) and maps it in
   `session_journal.h`: `00` prints `beacon`, `01` prints `eapol`, and any
   other ID prints `unknown`. The Mac check and a reader of the card then know
   which criterion applies to the PCAPs of the session.
1. Bump the format tag from `airrounds-session-v2` to `airrounds-session-v3`.
   Firmware v0.1 introduced v2 for the `firmware=` field; v3 keeps that field,
   adds `mode=`, and renames the counters.

For a Beacon round the counts are unchanged: `needs()` is `managementFrames`,
so `observedFrames` counts management frames exactly as before. A journal
consumer keyed on the v2 label names must read the v3 names.

## Timing

A beacon repeats about every 100 ms; a handshake occurs only when a client
joins. The AirRounds radio never forces a join, so the operator reconnects an
own client during the visit. The EAPOL mode therefore gets a longer budget per
point than Beacon.

| Mode | Budget per point | Listening per point | Five-point round |
| --- | --- | --- | --- |
| Beacon | 10 s, unchanged | Up to 7 s, the T8 windows | 50 s |
| EAPOL | 60 s | Up to the share minus 3 s | 300 s |

The budget per point includes radio setup and the save, as the comment at
`passive_round.h:130` states for Beacon: 10 s holds up to 7 s of listening and
3 s for setup and storage. EAPOL keeps the same 3-second reserve, so a point
listens for at most 57 s of its 60 s share.

- `passive_round.h:131` sets `visitBudgetUs = 10000000` for every round today,
  and `passive_round.h:83` sets the round deadline to
  `profile.size() * visitBudgetUs`. Replace the constant with
  `visitBudgetUs(uint8_t modeId)`: 10 s for Beacon, 60 s for EAPOL.
  `PassiveRound::start` knows the mode, because it calls `selectMode`, so it
  computes the deadline from the mode's budget.
- `VisitBudget::shareAt` (`passive_round.h:42` to 46) shares the remaining
  time across the points still to visit, as before. A point that stops early
  leaves the later points more time.
- `EapolMode::begin` stores `budgetUs`, the point's share. `EapolMode::done`
  returns true at `elapsedUs + saveReserveUs >= budgetUs_`, with
  `saveReserveUs = 3000000`, or early once messages 3 and 4 from one client
  are held. It applies no 5 s or 7 s window: the 7 s cap is
  `PassiveSession::maxAdaptiveWindowUs` (`passive_session.h:104`), which
  belongs to Beacon. Without the reserve, each save would shrink the later
  shares and the last save would run past the round deadline.
- A Beacon round keeps the 10 s budget, so its timing and its journal
  `budget_us` stay exactly as in T10.

The Flipper app has no round timer. It has the 900 ms request timeout and the
350 ms status poll (`session_client.h:176` to 178), and both apply per request,
not per round. A 300-second round therefore needs no client change. A host
test in `flipper_client_test.cpp` drives a fake clock through a 300-second
round and confirms that the link stays up. The T8 window tests in
`tests/uart/` cover the board side for both budgets.

During a visit the screen shows **Listening** and the network name, as for
Beacon. T11 adds no countdown, so a 60-second visit looks the same as a
10-second one.

The visit already tunes `target.channel` before `begin`
(`passive_visit.h:293`), so the EAPOL mode needs no channel plumbing. A
handshake on another channel stays invisible, which the target selection
already accepts.

## Writer defence in depth

The shared writer's frame-type gate is coarse. `frameTypeOf`
(`pcap_record.h:45`) reads only the 802.11 type bits, so a data mode could save
any data frame if `onFrame` had a parsing defect. The whole EAPOL-only promise
would then rest on `onFrame` alone.

Add a second, independent gate in the writer, keyed off the declared type.

1. Add `bool containsEapolEthertype(const uint8_t* frame, size_t size)` to
   `firmware/esp32/storage/pcap_record.h`. It rejects a frame that is not a
   data frame, has the Protected bit set, or has both DS bits set (a WDS
   frame, as `eapolBssid` drops it), re-derives the 802.11 header length, checks the LLC/SNAP header, and checks the ethertype `0x88 0x8e`. It
   does not classify the key-info, so it is a separate code path from the
   mode's classify logic.
1. In `detail::recordsAllowed` (`pcap_record.h:126`), whenever
   `allowedTypes & dataFrames` is set, require every data record to pass
   `containsEapolEthertype`. A mode that declares data and management frames
   cannot skip the gate. Management and control records are unaffected, so
   Beacon is unchanged.
1. Rewrite the existing case "a mode admitted for data frames saves one"
   (`tests/storage/capture_mode_test.cpp:190` to 195). It writes a data frame
   with no body, which the gate now refuses. Give it an EAPOL body, and add the
   refused case beside it.
1. Rewrite `testChainOfFrames` (`tests/storage/capture_mode_test.cpp:228` to
   262). Its 300-byte QoS data frame (`0x88` at line 232) has an all-zero body,
   so the assertion "a chain of admitted frames saves as one file" at line 239
   fails once the gate runs. Give the record a 26-byte QoS header, then
   `AA AA 03 00 00 00 88 8E` and EAPOL packet type 3, and keep it over 256
   bytes so it still spans queue blocks.

The gate re-implements the header-length, LLC/SNAP, and ethertype logic
locally and must not include `session/eapol.h`. Storage must not depend on
session. The two gates stay independent only while the writer has its own code
path. A reviewer who deduplicates the two reintroduces the single point of
failure.

The writer never calls the mode's parser, so a defect in `EapolMode::onFrame`
cannot bypass the gate. The writer refuses a non-EAPOL data frame before it
creates the file, and the whole set fails, as the writer already does for an
undeclared type. A future non-EAPOL data mode must revisit this gate, because
the gate ties a data capture to the EAPOL ethertype.

### Client reply parser

The client reply parser reads none of the new fields today. Add them as
follows.

1. `readReplyDetails` (`firmware/esp32/uart/uart_reply.h`) recognises

1. Add `case Outcome::absence_confirmed` to `pointResult` in

### Reply-budget fix

The board appends the round fields by command whatever the reply code, so a
rejected read also carries them. The
[design](capture-modes-design.md#protocol-reservation) counts the longest
rejected `round_status_mode` reply at exactly 239 bytes; a second count during
the T11 review reached 240 to 243. Either count leaves no spare byte. Before R5
adds the `mode` field, the board must leave the round fields off a rejected
reply, or the client reports a lost link. Build that first: a non-`ok` reply
drops the `aps`, `journal`, `interrupted`, and `mode` fields.

Settle the count in code, not in prose. A host test builds the longest
`round_status_mode` reply for every reply code and asserts that each one fits
`wireReplyCapacity`. The design document then quotes the measured length.

The fix changes every rejected-reply expectation that carries round fields.
Two are known: `tests/uart/protocol_test.cpp:806` expects `aps` on an
`unknown_session` reply, and the `readsCheckScopeAndArguments` loop (about
lines 812 to 835) expects `journal pending aps` on `unknown_session` replies
to `round_status` and `round_status_log`. Update them to expect no round
fields.

A client with bit 5 reads every round with `round_status_mode` and takes the
per-point results from that command only. The `round` and `round_stop`
replies carry the older encoding, which reports a confirmed absence as `1`.

## Mac check

`tools/mac/check_pcap.py` recognises only a beacon or a probe response today
(`observed_ssid`, line 32). Add an EAPOL criterion.

- Add a `--eapol` flag, used with `--bssid`. For each data frame the check
  derives the 802.11 header length, checks the LLC/SNAP header and the
  ethertype `0x88 0x8e`, confirms EAPOL packet type 3, and matches the BSSID by
  the DS bits, the same map as the firmware.
- For each matched frame the check classifies the handshake message from the
  key-info flags. It groups the frames by client, the non-BSSID address by the
  DS bits.
- It reports which messages the capture holds, per client.
- Every record must pass. A record that is not an EAPOL-Key frame for the
  BSSID, or a pairwise message the classifier cannot place, makes the file
  unsupported and exits 1. The firmware never writes such a record, so a
  failure here points at a writer or a mode defect.

The check reads only what the verdict needs, so it stays within
[saved frames][aup-saved]:

| Field | Read | Printed |
| --- | --- | --- |
| The 802.11 header, the LLC/SNAP header, the EAPOL packet type, and the key-info flags | Yes | The message numbers only |
| The target BSSID | Yes | Yes, as the check prints it for Beacon today: the operator's own access point |
| The client address | Yes, to group frames by client | No: the report numbers clients in order of first appearance, `client 1`, `client 2` |
| The nonce, the MIC, the key data, and any key-derived value | No | No |

T11 updates [saved frames][aup-saved] in acceptable use to state these limits.
The check derives nothing and decrypts nothing.

The Mac check is the only judge of a completed join. The board and the Flipper
report a saved frame; the check reports the join.

- Messages 3 and 4 from one client imply a completed join. A wrong passphrase
  repeats messages 1 and 2, so messages 1 or 2 alone do not imply a join.
- Count the messages per client, not per target. Message 3 to client 1 and
  message 4 from client 2 are not a pair. The check requires messages 3 and 4
  from the same client for a success.
- The exit code follows the T10 convention: 0 for a success, 3 for a matched
  BSSID with no completed handshake, 1 for a damaged or unsupported file. A capture
  that the board reported as "Captured" with only messages 1 and 2 exits 3: a
  saved frame, no confirmed join.

[acceptable use][aup-safeguards] relies on, so it uses an allowlist, not a
denylist. A denylist misses a transmit path nobody thought of; an allowlist
fails on any radio call nobody reviewed.

- **Files.** Every `*.h`, `*.c`, `*.cpp`, and `*.ino` under `firmware/esp32/`.
  Comments are scanned too: a comment that names a transmit call fails the
  test, which is cheaper than a comment parser that a macro can fool.
- **Radio API allowlist.** Every identifier that matches `esp_wifi_\w+`,
  `esp_now_\w+`, or `WiFi\.\w+` must be in this list, which is the set the
  firmware uses today: `esp_wifi_init`, `esp_wifi_deinit`, `esp_wifi_start`,
  `esp_wifi_stop`, `esp_wifi_set_storage`, `esp_wifi_set_mode`,
  `esp_wifi_set_channel`, `esp_wifi_get_channel`, `esp_wifi_get_country`,
  `esp_wifi_set_promiscuous`, `esp_wifi_set_promiscuous_rx_cb`,
  `esp_wifi_set_promiscuous_filter`, and
  `esp_wifi_set_promiscuous_ctrl_filter`. Any other match fails, for example
  `esp_wifi_80211_tx`, `esp_wifi_internal_tx`, `esp_wifi_connect`,
  `esp_wifi_scan_start`, `esp_now_send`, or `WiFi.begin`.
- **Radio mode.** Any `WIFI_MODE_` constant other than `WIFI_MODE_NULL` fails,
  because a station or access point mode can transmit.
- **Self-test.** The test copies the tree to a temporary directory, plants each
  example above in turn, and expects a failure for each. A gate that cannot
  fail proves nothing.

Adding a name to the allowlist is a reviewed change: the commit states why the
call cannot transmit.

### Mode cases

The `capture_mode_test.cpp` mode cases, built from synthetic EAPOL-Key frames:

- Accept a valid EAPOL-Key message 2 for the target BSSID, and save it.
- Drop a frame whose BSSID is not the target.
- Extract the BSSID for each DS form: `0x00` from Addr3, `0x01` from Addr1,
  `0x02` from Addr2, and drop the `0x03` WDS frame.
- Refuse a non-Key EAPOL type, a frame without the `0x88 0x8e` ethertype, a
  group rekey with the Key Type bit clear, and a WPA1 message 3 with
  `secure = 0`.
- Refuse a management frame and a data frame with the Protected bit set, in
  both `onFrame` and the writer gate.
- Accept a 512-byte message 3 with a full key-data block, and drop a frame one
  byte over the buffer instead of truncating it.
- Hold messages 1 to 4 and return them in capture order, including a repeated
  message 1 that arrives after message 2. Confirm the writer saves the chain
  as one PCAP with monotonic timestamps.
- Stop early on messages 3 and 4 from one client. Keep listening on message 3
  to client A and message 4 from client B, until the budget ends.
- Stop 3 s before the share ends when no complete handshake arrives.
- Confirm `found` with a lone message 1 maps to `saved`, and an empty visit
  maps to `not_observed`.

### RAM budget

`make embedded` is the memory gate. It measures the built images with
`tools/quality/memory.py` and fails on any of three limits. `tests/mac/test_memory.py`
only unit-tests that script with synthetic inputs, so it does not change with
the buffer size.

| Limit | Value | Source |
| --- | --- | --- |
| ESP32 global RAM | 65,536 bytes | `memory.py:21` |
| Stack frame of one function | 1,024 bytes | `memory.py:24` |
| Flipper session path | 2,048 bytes, half of `stack_size=4096` | `flipper/application.fam` |

- **ESP32 globals.** `PassiveVisit` holds `EapolMode` beside `BeaconMode`, so
  the four 512-byte frame buffers add 2,048 bytes, plus the sizes,
  timestamps, target, and budget. T10 measured 52,160 bytes of global RAM and
  13,376 free. That figure predates the v0.1 version work, so measure it
  again before the first firmware task and again after the visit wiring, and
  record both numbers in the T11 report.
- **Stack frames.** The 1,024-byte limit applies to stack frames, not to the
  capture buffers. `EapolMode` keeps its buffers as members, never on the
  stack, so `onFrame` stays far below the limit.
- **Flipper stack.** T10 measured 1,448 bytes on the session path. The client
  side of R5 adds a `modes` request and a reply field; measure the path again.

## Hardware acceptance

The bench uses an own access point with WPA2-PSK and an own client, such as a
phone. Nothing on the bench belongs to a third party. The operator reconnects
the client by hand during the visit; AirRounds never forces it.

| Run | Steps | Expected result |
| --- | --- | --- |
| Join | Start a one-point EAPOL round. Turn the client's Wi-Fi off and on during the visit. | The Flipper shows "Captured". `check_pcap.py --eapol --bssid` exits 0 and reports messages 3 and 4 for `client 1`. The journal shows `mode=eapol` and no underflow. |
| Wrong passphrase | Join the client with a wrong passphrase during the visit. | The Flipper shows "Captured". The Mac check exits 3: messages 1 and 2 only, no join. |
| No join | Start a one-point EAPOL round and leave the client alone. | The Flipper shows "Not seen" when the 60-second point ends. The card holds no PCAP for the point. |
| Beacon regression | Run a Beacon round on the same access point. | The same result, file, and 10 s budget as in T10. The journal shows `mode=beacon`. |
| Old board | Connect the v0.2 app to a v0.1 board. | The app does not offer EAPOL and runs Beacon. **About** shows v0.1 for the board. |
| Busy channel | Run the Join round while the client streams video before the reconnect. | The journal shows `queue_overflows=0` or a count the T11 report explains, the board does not reset, and the Join result holds. |
| Scan after EAPOL | Run **Scan area** after an EAPOL round. | The scan lists the networks as before; the data filter of the EAPOL visit does not stay set. |

WPA3-SAE is not tested on hardware in T11. The host tests cover a 512-byte
message 3, and the T11 report lists WPA3 as an open check.

Keep a flash backup and restore it after the bench, as in T9 and T10. Delete
the EAPOL captures when the acceptance ends, as
[data handling][aup-data] requires; keep only the Mac check output, which
holds no MAC address.

## Acceptance criteria

- `CaptureModeId::eapol = 1` exists, and `EapolMode` implements the contract
  with the clean-room `onFrame`.
- A Beacon round behaves exactly as in T10: the same frames, the same windows,
  the same PCAP bytes, and the same journal values under the v3 labels.
- An EAPOL round on an own access point, with a client that joins, saves a PCAP
  that `check_pcap.py --eapol --bssid` reports as a completed handshake.
- A point that saves at least one EAPOL-Key frame reports `saved` and the
  Flipper shows "Captured", whether or not the capture is a completed join.
- An EAPOL round with no EAPOL-Key frame for the target reports `not_observed`
  and writes no file.
- The writer refuses a non-EAPOL data frame before it creates the file.
- The journal shows no underflow for an EAPOL round.
- The client reads `round_status_mode` with the `mode` field and result digit
  5, and still rejects digit 5 in a `round` reply.
- No transmit call exists under `firmware/esp32/**`, and the receive-only test
  proves it.
- The host suite passes `make check`, `make asan`, `make tsan`, and
  `make embedded`, and `make embedded` stays within every memory limit with
  the 512-byte buffer.
- The Flipper app offers EAPOL only when the board reports bit 5 and lists
  `01`.
- The Mac check prints no client MAC address and reads no nonce, MIC, or key
  data.
- An EAPOL round budgets 60 s per point and each point listens up to its
  share minus the 3-second save reserve; a Beacon point keeps 10 s; no client
  timer fails during a 300-second round.
- The PCAP records come in capture order, and the board stops early only on
  messages 3 and 4 from one client.
- Every run in [Hardware acceptance](#hardware-acceptance) passes on the
  WPA2-PSK bench.
- Firmware and app report v0.2, and every document in
  [Documentation changes](#documentation-changes) matches the shipped firmware.
