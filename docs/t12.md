# T12 active EAPOL capture requirements

T12 adds AirRounds' first active capture mode. The mode transmits
deauthentication frames to force one client off an approved access point, so the
client rejoins and produces a WPA 4-way handshake the mode then captures. It
realises the reserved Todo B slot in the [capture-mode contract](capture-modes-design.md).

This mode inverts the project's founding receive-only property. The author
approved it on 22 November 2026 under the limits in this document and in the
[active operation](acceptable-use.md#active-operation) section of the acceptable
use policy. This phase writes the requirements, the design, and the architecture.
It writes no firmware code.

## Why the mode exists

The passive [EAPOL mode](t11.md) captures a handshake only when a client joins on
its own, which can take hours or never happen in a round. T12 forces the join, so
an operator can measure on demand what an attacker with deauth capability could
collect from the operator's own network.

The mode adds force, not a new capability. A beacon already carries the RSN
capability bits that reveal whether an access point mandates 802.11w Protected
Management Frames, which defeats deauth. The passive tool already answers "is this
network exposed to deauth" without transmitting. T12 is worth its cost only where
the operator needs the handshake now, not where they need the exposure answer.

## Approved decisions

A requirements survey settled four decisions. Each one binds the design and the
architecture.

| Decision | Choice |
| --- | --- |
| Scope | The active mode is opt-in. The passive tool stays the shipped default. |
| Build | A separate opt-in transmit build target. The default image stays provably receive-only. |
| Policy | A tiered acceptable use policy: the passive policy, plus an active section with its own limits and an operator attestation. |
| Safety envelope | Targeted unicast deauth only; bounded burst and a hard per-round transmit cap; a kill switch and auto-stop on capture; a transmit audit log. |

## What the mode does

The mode runs as one visit's capture mode, like Beacon and EAPOL, under the
[capture-mode contract](capture-modes-design.md#the-capture-mode-contract). It
differs from passive EAPOL in one way: it transmits a bounded deauthentication
burst at one targeted client, then captures the handshake the rejoin produces.

- The mode deauthenticates one client on the visit's approved access point. It
  sends a unicast deauthentication frame to that client's MAC address.
- The mode captures the EAPOL-Key frames of the rejoin, under the same writer and
  the same frame-type gate as passive EAPOL.
- The mode stops transmitting the instant it captures a handshake, and it never
  exceeds the per-round transmit cap.

## Active mode limits

These limits extend the four passive limits in
[acceptable use](acceptable-use.md#capture-modes-in-scope). They bind the active
mode in addition to the passive four, except that the active mode transmits.

| Limit | Rule |
| --- | --- |
| Approved target only | The mode transmits only to a client on one of the round's approved access points, which the operator owns or has written permission to test. |
| Unicast only | The mode sends a deauthentication frame to one client address. It never broadcasts a deauthentication frame. |
| Bounded transmit | The mode sends a small burst, and at most two bursts per visit, under a hard per-round transmit cap. |
| Auto-stop | The mode stops transmitting the instant it captures a handshake. A kill switch stops it at any time. |
| Audit | The journal records every transmitted frame: the count, the target access point, the target client, and the time. |
| No decryption | The mode decrypts nothing and derives no key, as passive EAPOL does not. |

## Out of scope

These stay prohibited. The design must make each one impossible or absent, not
merely discouraged.

- Broadcast deauthentication, or any transmit that hits a client the operator did
  not target on an approved access point.
- A continuous or unbounded deauthentication stream.
- Deauthenticating a device on a network the operator does not own or is not
  permitted in writing to test for active transmission.
- Any transmit other than the targeted deauthentication frame.
- Decryption, key derivation, or any offline password attempt.

## Constraints

- **Clean-room only.** pwnagotchi and esp32-marauder are both GPL-3.0. The
  project's PolyForm Noncommercial policy bans copying GPL code into the tree; see
  [acceptable use](acceptable-use.md#adding-third-party-code). Reimplement the
  deauthentication frame from the IEEE 802.11 standard. Do not read a GPL
  implementation first, because that taints the clean-room claim. A deauthentication
  frame is a fixed structure defined by the standard, so the technique needs no
  third-party source.
- **Regulatory exposure.** The FCC treats Wi-Fi deauthentication as prohibited
  jamming under 47 U.S.C. section 333. The operator carries this risk. For a
  permitted network the operator does not own, the written permission must name
  active transmission, not testing alone. This document is not legal advice.
- **Assurance downgrade.** The passive build gate proves the absence of a
  transmit capability. An active build can prove only that the transmit path is
  confined to one reviewed file. The architecture keeps the default build's
  stronger proof intact.

## Acceptance criteria

The acceptance report defines its evidence in the architecture stage. These are
the criteria it must meet.

- The default build stays provably receive-only: `tests/mac/test_receive_only.py`
  passes against it unchanged.
- The active build's transmit path is confined to one reviewed file, which a gate
  variant proves.
- The mode transmits only a unicast deauthentication frame to an approved client,
  within the burst and per-round caps, and stops on capture.
- The burst size and the per-round transmit cap are compile-time limits an
  operator cannot raise.
- The journal records every transmitted frame.
- Every host memory gate passes: `make check`, `make asan`, `make tsan`, and
  `make embedded`.
- A WPA2-PSK bench run on an own network captures a handshake, with the transmit
  measured.

## Acceptance status

The firmware, the protocol, the Flipper descriptor, and the journal audit are
built on the branch `feat/t12-active-eapol`, in steps A1 to A6 of the
[architecture plan](t12-architecture.md#code-steps). The WPA2-PSK bench passed on
the Devboard: a Deauth round forced a client rejoin, captured the EAPOL handshake,
and recorded the transmit.

| Area | Status |
| --- | --- |
| Software gates | `make test`, `make asan`, and `make tsan` pass. `make embedded` builds both images. |
| Default build receive-only | `tests/mac/test_receive_only.py` passes unchanged and now also asserts that no `firmware/esp32/` file includes `firmware/active/`. |
| Active build confinement | `tests/mac/test_active_transmit.py` confines the one `esp_wifi_80211_tx` call to `firmware/active/`. |
| Host tests added | `deauth_frame`, `active_eapol_mode`, `active_protocol`, `active_journal`, and `check_journal`. |
| Transmit audit | The active journal is format v4 with a per-point `tx` line; `tools/mac/check_journal.py` verifies it. |
| Hardware bench | Passed on the Devboard: deauth transmitted (`ESP_OK`), client rejoined, EAPOL messages 1 and 2 captured and saved, audit recorded `tx frames=3`. |

The host `make check` format gate is red on a machine whose clang-format is newer
than the one the repository was formatted with; it flags pre-existing lines across
the repository, not the T12 code. Pin the formatter version before relying on that
gate. See the [architecture plan](t12-architecture.md).

### Hardware bench

The bench ran on the Devboard against an own WPA2-PSK network, with the connected
client generating uplink traffic.

| Check | Result |
| --- | --- |
| `esp_wifi_80211_tx` transmits in `WIFI_MODE_STA` with promiscuous receive on. | Pass. The transmit returned `ESP_OK`. |
| The spoofed-source deauthentication frame leaves the radio. | Pass, with the sanity-check override and `-Wl,-zmuldefs`. See [the raw-frame sanity check](t12-architecture.md#the-raw-frame-sanity-check). |
| The burst delivers three frames. | Pass. The journal recorded `tx frames=3`. |
| A full round captures the handshake. | Pass. The mode captured EAPOL messages 1 and 2, a crackable set, and auto-stopped. |
| The **Deauth** row fits the Flipper screen. | Pass, confirmed on a device screenshot. |
| The station radio emits nothing but the deauthentication burst. | Pass. No probe, authentication, or association frames during a round. |

The transmit auto-stopped on the crackable set, so a round captures EAPOL messages
1 and 2, not always all four. Messages 1 and 2 carry the ANonce, the SNonce, and
the MIC, which is the set an offline analysis needs.

Two checks stay open. An 802.11w target should produce a `not_observed` result,
not an error; the bench network does not mandate Protected Management Frames. The
version bump for the active build is a release decision; the default build stays
v0.2.

### Follow-ups

- TODO: add a microSD preflight. A round started with no card inserted runs to
  completion and saves nothing; the mount fails only at save time, reported as
  `storage_error`. Detect a missing or unmountable card before the round starts,
  and warn the operator on the Flipper, so a round is not wasted. Seen on the T12
  bench, where a round ran with no card and wrote no capture.
- TODO: make the active mode's target discovery robust to an idle client. A
  Deauth round on the bench recorded `tx frames=0` because the connected client
  sent no uplink frame to the target within the window, so no client was latched
  and no burst fired. Consider a longer discovery window, or a note that the
  operator should generate client traffic, until a client is observed.

## Open questions

The design and the architecture stages resolved these, and the implementation is
on the branch. The [hardware bench](#hardware-bench) passed.

| Question | Resolution |
| --- | --- |
| The radio mode for the transmit. | `WIFI_MODE_STA`, confined to `firmware/active/`; the bench confirms it. See [radio mode](t12-architecture.md#radio-mode). |
| Excluding the transmit file from the default gate, and proving confinement. | `tests/mac/test_active_transmit.py` with the include-assertion in `tests/mac/test_receive_only.py`. |
| The `poll` cadence and the round-scoped transmit cap. | `ActiveEapolMode::poll` paces the burst; `TransmitBudget`, seeded per round in `PassiveRound`, caps it. |
| The Mac check for the transmit audit. | `tools/mac/check_journal.py`. |
